# Участие в разработке

Изменения в CajeerEngine Lite должны учитывать назначение независимой Lite-редакции, совместимость схемы и безопасное самостоятельное размещение.

## Рабочий процесс

1. Опишите проблему или предлагаемое изменение: версия, среда, ожидаемое и фактическое поведение. Не включайте приватные данные.
2. Создайте отдельную ветку от актуального исходного дерева. Проверяйте изменения на изолированном экземпляре, а не production.
3. Добавьте регрессионный сценарий, обновите релевантные руководства и changelog. Не меняйте VERSION или схему без согласованного релиза.
4. Откройте pull request с описанием, списком затронутых компонентов, результатами проверок и рисками миграции/отката.

## Проверки

```bash
php tests/smoke.php
php tests/core_210.php
bash tests/http.sh
```

Дополнительно запускайте профильные тесты из `tests/` и полный workflow `.github/workflows/ci.yml`. Для релизной автоматизации — `python3 tests/release_ga_160.py` на изолированном стенде. Не выдавайте непройденные тесты за успешные; реальные провайдеры и production требуют отдельной приёмки.

## Безопасность и публикация

Не включайте в PR пароли, API-ключи, приватные ключи подписи, `storage/` рабочего сайта или искусственное evidence. Сведения об уязвимостях отправляйте приватно по [SECURITY](SECURITY.md). Релизы выпускаются по [RELEASE](docs/RELEASE.md), а не изменением уже опубликованных тегов и артефактов.
