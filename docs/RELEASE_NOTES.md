## Главное в релизе

**Управляемый жизненный цикл обновления.** Релизная автоматизация требует exact-base пакет для 1.5.9 RC и при наличии тегов добавляет базы 1.5.7/1.5.8. Главная база — предыдущий опубликованный Stable. Подписанный индекс и каждый переход проверяются отдельно.

**Защита от неоднозначного прерывания установки.** Supervisor фиксирует фазу `installing` до запуска worker. Если транзакция завершилась, но результат установки остался неопределённым из-за сбоя, новый runtime не принимается автоматически: выполняется откат этой транзакции. Неизменившаяся база восстанавливается без отката постороннего receipt.

**Проверка реальной публикации.** `release ga-check` в live-режиме заново обращается к точному тегу GitHub, проверяет статус Stable, состав и байты всех артефактов, подпись, runtime, managed trust, мониторинг и состояние scheduler. `ga-sign-off` дополнительно связывает результаты с операторскими доказательствами.

**Независимый preflight.** Root-owned supervisor проверяет реальные systemd units, guards, timer, доверие и loopback HTTPS без запуска установки.

## Переход на 1.6.0

- Для 1.5.9 необходим подписанный пакет именно с базы 1.5.9 либо независимо проверенный ручной переход. Не используйте пакет другой базы.
- Для Stable определите достижимый маршрут по подписанному индексу. Не обещается прямой переход с каждой исторической версии.
- Сохраните независимые резервные копии и остановите все процессы записи на время ручного обновления.
- Обновите отдельно привилегированные supervisor и guard; старый supervisor не понимает новую фазу `installing`.
- Сначала проверьте staging, затем настройте opt-in, UTC-окно и канал Stable. Preview оставьте выключенным.

## Что не меняется

Схема JSON 14, формат обновления и функции CMS не требуют новой миграции при переходе с актуальной схемы. Опциональные провайдеры остаются опциональными. Полный ZIP для чистой установки отличается от подписанного инкрементального пакета и архива изменённых исходников.

## Условия фактического выпуска

Официальные ключи, защищённые теги и GitHub publication, реальный PHP-FPM/systemd/TLS, тестирование провайдеров, нагрузочная эксплуатация и человеческая приёмка должны быть подтверждены оператором. В исходниках есть workflow и тестовые сценарии; их наличие не свидетельствует о выполнении этих действий. Не публикуйте искусственные доказательства как результаты production.
