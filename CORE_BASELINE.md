# Совместимость ядра с CajeerEngine 2.1.0

CajeerEngine Lite 1.0.1 использует **собственное** минимальное приложение и сохраняет JSON-хранилище схемы `1`. Это **не** установка полной CMS CajeerEngine 2.1.0.

Из переданного архива CajeerEngine 2.1.0 синхронизированы оригинальные классы:

- `core/Template/CajeerTemplateEngine.php` и `TemplateExpressionEvaluator.php` — актуальные исходники 2.1.0.
- `core/Template/TemplateCompiler.php`, `TemplateSandbox.php`, `core/Public/PublicPath.php` — уже совпадали с кодом 2.1.0, менять не требовалось.
- `core/Update/OperationFiles.php` — актуальные исходники 2.1.0, включая проверку всех компонентов пути при создании каталогов.
- `core/Update/OperationLock.php` — оригинальные примитивы блокировок 2.1.0; Lite использует `openLockFile` для синхронизации изменений сайта.

`core/Lite.php` интегрирован с `OperationFiles` и `OperationLock`: запрет подменённого JSON/lock-файла и symlink-каталогов, атомарная запись с синхронизацией каталога, защита от параллельных изменений через `flock`. Не требуется Composer, SQL или Redis. Существующий `storage/site.json` (schema 1) совместим, миграция данных не нужна.

## Что не включено

Подсистемы полной CMS 2.1.0 (API, БД, Nuxt Admin, работники очередей, обновление с Ed25519-подписью, восстановление, Update Center и системный оператор) **не** включены: они зависят от полного ядра, Composer и инфраструктуры CMS. Перенос их в Lite без полного редизайна изменил бы продукт и не представлял бы собой безопасное обновление. Lite по-прежнему **не предоставляет автоматического обновления**. Версия приложения Lite — `1.0.1`; `ENGINE_BASE_VERSION = 2.1.0` обозначает уровень синхронизированных общих компонентов.

## Проверка

```
php tests/smoke.php
php tests/core_210.php
bash tests/http.sh
php bin/cajeer doctor
```

Последняя команда выполняется после установки. Использовать PHP 8.4.1+ и размещать каталог проекта за пределами DocumentRoot (`public/`).
