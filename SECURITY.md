# Политика безопасности

**CajeerEngine Lite 1.6.0**

## Защищённое развёртывание

- Используйте локальное односерверное размещение по [INSTALL](docs/INSTALL.md) и [COMPATIBILITY](docs/COMPATIBILITY.md). Обновляйте PHP, OpenSSL и системные зависимости из доверенных источников. Наличие аудита в проекте не является независимым pentest или CVE-сертификацией.
- Document root — только `public/`. Хранилище, TAR, шаблоны, резервные копии и recovery-файлы не должны раздаваться веб-сервером. Код доступен HTTP worker только для чтения. Запись шаблонов (`CAJEER_DEVELOPER_TEMPLATE_WRITE`) разрешайте только в авторизованное окно.
- Используйте HTTPS, корректный canonical origin, защищённые cookie, точные доверенные IP прокси и firewall. Прокси перезаписывает, а не пропускает клиентские forwarded-заголовки.
- Установите уникальный пароль администратора; для SkiF4er ID зарегистрируйте точный callback и проверьте реальный login/logout/revocation. Не используйте production credentials в CI. Не записывайте токены и пароли в журналы.
- Ключи API и TLS, секреты окружения и ключ подписи хранятся отдельно от исходников. Используйте managed trust для GA. Не доверяйте ключу из скачанного релиза, не отключайте TLS verification и не принимайте неподписанные пакеты. При компрометации приостановите обновления, отзовите ключ и проверьте runtime. Подробнее: [доверие и ротация](docs/UPDATE_SECURITY_HARDENING.md).
- Импортируйте только проверенные архивы, не распаковывайте произвольный TAR в web root. При ошибке сохраняйте recovery markers. Приватные данные не должны входить в релизные артефакты.

## Аудит и инциденты

```bash
php bin/cajeer security audit --json
php bin/cajeer compatibility check --json
php bin/cajeer update trust status
```

Локальный inventory не является онлайн-сканером CVE. Проверяйте системные advisories и используемые CI actions отдельно. При подозрении на компрометацию изолируйте сервер, остановите записи и обновления, сохраните журналы и резервные копии, смените затронутые секреты из доверенной среды. Восстановите согласованные код и данные из проверенного источника, затем проверьте авторизацию, сессии и интеграции.

## Ответственное раскрытие

Сообщайте о найденных уязвимостях приватно: `security@cajeer.ru` или через механизм GitHub private vulnerability reporting, если он включён в репозитории. Укажите версию, минимальное воспроизведение на собственном изолированном стенде, влияние и обезличенные диагностические данные. Не публикуйте секреты, чужие данные и exploit payloads; не тестируйте чужие установки без разрешения. Согласуйте раскрытие с сопровождающими. Политика не обещает bounty или SLA ответа.
